# 通知悬浮气泡 · 0.4.0 测试工程

目标：iPhone 14、iOS 16.0.3、Dopamine RootHide。

源码及打包文件检查已完成；本版本尚未在 GitHub 编译、尚未真机验证。不要把文件检查当作功能验证。

## 更新已有仓库

1. 解压新版，进入 `NotifyBubbles` 文件夹。
2. 在 GitHub 仓库根目录点击 **＋ → Upload files**。
3. 上传覆盖 **Sources、Preferences、Tests、scripts、Makefile、control、README.md**。
4. 本次必须更新根目录 **Makefile**，因为新增了切换器适配文件；遗漏会导致链接失败。已有 `.github/workflows/build.yml` 不用改。
5. 提交后打开 Actions，进入最新构建。成功后在 Artifacts 下载 **NotifyBubbles-RootHide**。
6. 解压得到版本 **0.4.0** 的 `.deb`，安装后重启桌面。

新建仓库则上传完整目录内容，包括隐藏的 `.github` 文件夹；根目录直接放 Makefile，不要套一层 NotifyBubbles。

## 本版行为

| 操作 | 结果 |
| --- | --- |
| 点击有待处理通知的图标 | 按通知时间由新到旧，每次提交一条通知的系统默认打开动作 |
| 队列为空时点击 | 使用 SpringBoard 的正常 App 打开接口，不再重放已点过的旧通知 |
| 点击半隐藏图标 | 在同一次点击事件里开始伸出动画并立即提交打开动作，无需等动画结束 |
| 新消息 | 对应 App 图标移到第一位，其他图标动画让位 |
| 伸出与缩回 | 均约 0.6 秒，完整伸出后停留 2 秒；新消息/点击重新计时 |
| 锁屏显示关闭 | 仅隐藏，不停止收集；进入允许显示的位置后伸出图标 |
| 切换器卡片 | 没有通知的 App 也会获得可直接打开的图标 |
| 单独上划关闭卡片 | 对应图标破裂消失 |
| 一键清空切换器 | 按当时图标顺序，每隔约 0.16 秒启动一个破裂动画 |
| 向右划图标 | 拖动超过 20 点或快速右划后关闭图标，保留破裂动画；不会关闭后台 App |
| 长按 | 不再关闭图标 |

图标大小 32–80 点，不透明度 20%–100%；闲置露出半个圆形图标。锁屏、主屏、App 内独立开关仍保留。桌面角标由系统提供，插件不修改它。系统“减弱动态效果”开启时减少动画。

右划关闭后，切换器中原来的同一张卡片不会立即把图标加回来；新消息到达或卡片移除后重新进入切换器，图标可再次出现。清理时新到达的通知通过版本校验保留，不会被旧清理动画误删。

## 通知与未读的边界

队列保存插件运行期间实际收到、尚未通过图标提交打开的系统通知，按通知时间排序。插件不能直接读取每个 App 内部的真实已读数据库。App 撤回通知、系统清除通知或已观察到的桌面角标从正数清零时，会更新队列。禁用角标的 App 仍按系统通知队列处理。

解锁状态下，正常提交通知动作后从本地待处理队列移除该条；这不等于直接修改 App 内部已读状态，也不等于系统保证跳转成功。锁屏下等待解锁并检测到对应 App 前台后再移除，取消认证则保留。私有接口行为必须真机验证。

没有待处理通知时调用正常 SpringBoard App 打开接口，不调用绕过锁屏接口；系统若拒绝锁屏启动，请解锁后重试。图标列表不跨重启桌面保存。原横幅和通知中心保留。

## 切换器适配范围

使用系统 `recentAppLayouts` 卡片列表做差异检测，约每 0.5 秒检查一次。逐个上划对应逐个清理；一键清理不依赖第三方插件名称，但该插件必须实际移除切换器卡片。仅结束进程而保留卡片的清理模式不会触发移除。

非空变空需连续两次确认；接口无法读取或卡片格式不匹配时按“未知”处理，避免误清空图标。不同系统私有接口仍可能需要真机调整。锁屏期间暂停切换器清理检测，但继续收集通知。

## 真机验收

- [ ] 同 App 收到三条不同通知，连续点击按最新、中间、最旧顺序提交动作；之后直接打开 App。
- [ ] 点击一个 App 不消费另一个 App 的通知；同一通知重复投递不重复计入。
- [ ] 半隐藏图标点击即打开，伸出动画同时开始，没有额外等待。
- [ ] 收到新通知的图标移到第一位，其他图标平滑换位。
- [ ] 两个方向都是约 0.6 秒，完整伸出后停留 2 秒。
- [ ] 关闭锁屏显示后，锁屏收消息、解锁进桌面仍出现图标。
- [ ] 切换器中没有消息的 App 也出现图标，点击正常打开。
- [ ] 逐个上划卡片，对应图标逐个破裂；一键清空后全部从上到下破裂。
- [ ] 清理期间新消息图标保留；重新打开的 App 不被旧清理任务误删。
- [ ] 右划关闭保留破裂效果，竖向滚动不误关，取消右划回到原位；长按不关闭。
- [ ] 锁屏认证取消不消费消息；尺寸、透明度、横屏、键盘和触摸区域正常。

## 验证与故障

Actions 先运行实际通知状态类的测试，再编译，并检查 DEB 架构和有效载荷。本机 `python scripts/validate.py` 只验证项目文件、LF 换行、设置项和打包配置。

编译报错时下载 `NotifyBubbles-build-log`；手机无图标时查看 SpringBoard 日志中 `[NotifyBubbles]` 记录。桌面异常时通过 Dopamine 不加载插件的方式进入系统并卸载本插件，不要删除系统文件。

包架构为 `iphoneos-arm64e`，仅供目标 RootHide 环境。通知只用于本机系统打开动作；插件无联网代码，不将消息正文写入文件。
